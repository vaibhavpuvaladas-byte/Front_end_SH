# AI Agent Instructions: Gigly Frontend Implementation

## 1. Project Overview
**Gigly** is a blockchain-powered escrow platform designed for the gig economy. It allows clients and freelancers to transact in USDC without touching crypto wallets or paying gas fees directly.

## 2. Frontend Technology Stack
- **Framework:** Next.js + React
- **Web3 Integration:** Thirdweb React SDK v5
- **Hosting:** Vercel or Netlify (Free Tier)
- **Key External APIs:** `open.er-api.com` (for INR conversion fallback)

## 3. UI/UX Design Requirements
- **Vibe:** Clean, professional freelance-marketplace (similar to Fiverr/Upwork), with a Stripe-like fintech tone.
- **Terminology:** ABSOLUTELY NO blockchain jargon (hide wallet addresses, gas, transaction hashes). Use plain English like "Payment secured", "Processing", "Paid".
- **Color Palette:** Neutral base (white/light gray) with a teal/green accent for primary actions. Status colors: Green (success/released), Amber (pending), Red/Coral (disputed).
- **Typography:** Modern, clean sans-serif. Use sentence case (no all-caps).
- **Components:** Rounded cards (12px radius, soft 1px borders, no heavy shadows). Job statuses should be pills/badges.

## 4. Authentication & Wallet (Thirdweb)
- Implement `ConnectButton` from Thirdweb.
- **Login Methods:** Google OAuth + Email OTP (in-app wallet).
- **Wallet Setup:** Enable ERC-4337 Account Abstraction (`executionMode: "EIP4337"`) and sponsor gas (`sponsorGas: true` via Thirdweb Paymaster).
- **Post-Login:** Show a role picker ("I'm hiring" vs "I'm working") and save this choice against the wallet address.

## 5. User Flows & Dashboards

### A. Client Path
- **Dashboard:** Two main tabs: "Browse freelancers" and "My jobs". Top metric cards for active jobs, total spent, etc.
- **Browse Tab:** Static directory of freelancers (avatar, name, skill tag, hidden wallet address).
- **Fund Job:** Selecting a freelancer opens a form to enter task title and USDC amount -> triggers `createJob` contract call (gasless).
- **Review Tab:** Shows submitted work with options to "Approve" (`approveAndRelease`) or "Dispute" (`raiseDispute`).

### B. Freelancer Path
- **Dashboard:** Two main tabs: "Incoming tasks" and "Earnings".
- **Task Visibility:** Must be near-instant and event-driven. Listen for `JobCreated` events where `freelancer == myAddress`.
- **Submit Work:** "Submit work" button calls `submitWork(jobId)`. This starts a 24-hour review countdown.
- **Claim Payment:** Button appears only after 24h of no client action, calling `claimAfterWindow`.
- **Currency Dashboard:** Shows USDC balance live, converting to EUR (via Chainlink on-chain) and INR (via fallback API). Must refresh every 30 seconds.

### C. Admin Path
- **Dashboard:** Internal view listing disputed jobs.
- **Resolution:** Arbiter calls `resolveDispute` to split funds.

## 6. Development Phasing for Frontend
1. **Setup & Auth:** Next.js scaffolding, implement Thirdweb ConnectButton, confirm gasless tx.
2. **Client Dash:** Build static directory, "Fund a job" flow, and job list via event filters.
3. **Freelancer Dash:** Build incoming tasks list, submit work flow, and the currency dashboard (30s refresh).
4. **Review/Dispute Flow:** Add approve/dispute UI for clients and claim UI for freelancers.
5. **Polish:** Remove raw hex addresses, ensure human-readable statuses, handle empty/error states (e.g., stale oracle data, wallet connect failure).

1. Product Requirements Document (PRD)
App name: Gigly
One-line idea: A gig-economy escrow platform where clients fund jobs in USDC, freelancers get paid
automatically or after review, and neither side ever needs to touch a crypto wallet directly.
Target users - Clients - individuals or small businesses hiring freelancers, often across borders, who want
payment security without slow bank wires or high platform fees. Freelancers - gig workers, especially
in markets like India, who want fast, low-fee payouts and a clear view of what their earnings are worth in
local currency. Arbiter (platform team)
resolves disputes when a client and freelancer disagree on
delivered work.
Problem being solved Cross-border freelance payments are slow, expensive (wire fees, FX markups),
and offer little protection if a client refuses to pay or a freelancer doesn't deliver. - Freelancers in emerging
markets are especially exposed to currency volatility and delayed settlement. - Crypto/blockchain rails could
fix this, but are normally too technical for non-crypto-native users (seed phrases, gas fees, wallet apps).
Core features (MVP) Login via Gmail or email no seed phrase, no wallet app, no gas tokens ever
required - Client dashboard: browse a directory of freelancers, assign and fund a task - Freelancer dash-
board: see incoming tasks in real time, submit completed work - Optimistic escrow: 24-hour review window,
client can approve early or let it auto-release - Dispute path: client can freeze a payment inside the window;
platform arbiter resolves the split Real-time currency dashboard: freelancer's USDC balance shown live
in INR and EUR
User roles: Client, Freelancer, Arbiter (internal/admin only)
User stories - As a client, I want to fund a job so the freelancer knows I'm serious and payment is guaranteed
on delivery. - As a client, I want to review submitted work and only release payment once I'm satisfied, or
dispute it if I'm not. As a freelancer, I want to see a task appear the moment a client assigns it, without

worth in my home currency, live. - As a freelancer, I want to be paid automatically if the client simply doesn't
respond in time.
Success metrics - Successful job completion rate (released / total funded jobs) - Dispute rate (disputed /
total jobs) - Median time from work submission to payment release - Signups per role (clients vs freelancers)
MVP scope - Single chain: Polygon Amoy testnet only - Single settlement asset: self-deployed Mock USDC
- Login: Gmail OAuth + email OTP (Thirdweb in-app wallet) - Lump-sum escrow jobs (milestone support
